# Statement Import

Тестовое задание Mobile Engineer: надёжный импорт синтетической банковской выписки на React Native и TypeScript.

**Реализованы импорт, восстановление и удаление операции.** После выбора и локальной проверки PDF/CSV приложение просит подтвердить отправку, сохраняет случайный ключ и собственную копию файла до POST, отправляет настоящие байты и получает результат через GET. Реализованы повтор после потерянного ответа, восстановление при запуске без автоматической повторной отправки и защита от старых статусов. Удаление требует подтверждения, использует отдельный сохранённый ключ и завершается после GET со статусом `deleted`; ошибка допускает повтор с прежним ключом. После очистки можно начать новый импорт. Всё находится внутри фичи `statement-import`. Кандидат подтвердил ручной прогон и запись видео для iOS и Android 3 ноября 2026 года; границы инструментальных проверок и оставшиеся пункты приведены в матрице приёмки. Выданные сервер и фикстуры сохранены без изменений.

## Структура

```text
mobile/                         Приложение Expo, React Native и TypeScript
  App.tsx                       Точка входа, экспорт корневого приложения
  src/
    app/App.tsx                 Сборка приложения и общие провайдеры
    features/
      statement-import/
        index.ts                Публичный API фичи
        api/                    POST/GET/DELETE, проверка ответов и тесты HTTP-контракта
        lib/                    Picker, валидация и журнал сохранённой операции
        model/                  Выбор, импорт, восстановление, удаление, hooks и тесты
        ui/                     Подтверждения, состояния, результат и подробности
  app.json                      Нативная конфигурация iOS и Android
  ios/                          Сгенерированный проект Xcode, игнорируется Git
  android/                      Сгенерированный проект Gradle, игнорируется Git
  package.json                  Зависимости и команды клиента
  package-lock.json             Зафиксированное дерево зависимостей
  patches/                      Воспроизводимые исправления зависимостей
docs/                           Документация задания и план работ
mobile-engineer-kit/            Неизменённый локальный mock и фикстуры
mobile-engineer-test-task.pdf   Исходное задание
package.json                    Короткие команды из корня проекта
```

Код организован по фичам. Весь сценарий импорта, включая восстановление, результат и удаление, принадлежит `statement-import`. Файловый адаптер, API, хранилище и модели выбора и операции находятся внутри этой фичи. Общий `shared` появится, когда понадобится переиспользуемый код; сейчас такой папки нет. Правила зависимостей описаны в [архитектуре](docs/architecture.md).

## Подготовка

Используется официальный `expo-template-blank-typescript@58.0.30`: Expo SDK 58, React Native 0.88.1, React 19.3 и строгий TypeScript. Нативный клиент содержит `expo-dev-client`, `expo-document-picker ~58.0.4` и `expo-file-system ~58.0.13`; Expo Go и web для этого задания не используются.

Для клиента нужен Node.js, совместимый с установленным React Native: `^22.13.0`, `^24.3.0` или `>=26.0.0`. В `.nvmrc` указан проверяемый локально Node.js 22.16.0. Для самого mock достаточно Node.js 20+.

Для нативной сборки дополнительно нужны Xcode с iOS Simulator и CocoaPods либо Android Studio с Android SDK, JDK и эмулятором. **Expo SDK 58 требует Xcode 26.4+** согласно [таблице совместимости Expo](https://docs.expo.dev/versions/v58.0.0/).

Expo SDK 58 и архитектура по фичам сохранены. Окружение обновлено до macOS 27.2 / Xcode 27.2 (27B52). 1 ноября 2026 года после добавления picker новая iOS-сборка завершилась `BUILD SUCCEEDED`, установлена и запущена на iPhone 16 Plus Simulator / iOS 18.2; системный диалог Files открылся. Результаты выбора конкретных документов фиксируются отдельно в [матрице приёмки](docs/acceptance.md). Прежняя ошибка Xcode 16.2 осталась в [истории диагностики](docs/ios-troubleshooting.md). Официальная инструкция: [локальная сборка Expo](https://docs.expo.dev/guides/local-app-development/).

Для чистого checkout:

```sh
git clone https://github.com/VarfolomeevRoman/statement-import.git
cd statement-import

# Если установлен nvm:
nvm use

# Все зависимости клиента устанавливаются в mobile/.
npm --prefix mobile ci
```

В корне зависимостей нет; отдельный `npm install` здесь не нужен. Mock не требует установки пакетов. Установка зависимостей и первоначальная подготовка нативных инструментов требуют сети; работа с готовым mock не требует аккаунтов, токенов или внешнего API.

`npm ci` автоматически применяет патч React Native 0.88.1 через `postinstall`. Он исправляет обработку UTF-8 путей в Hermes при установке CocoaPods, в том числе для папки с кириллицей. Устанавливайте зависимости с lifecycle scripts; подробности и порядок пересмотра патча при обновлении React Native — в [диагностике iOS](docs/ios-troubleshooting.md).

## Нативные проекты iOS и Android

Каркас создан с Expo Continuous Native Generation (CNG). Поэтому сразу после создания приложения папок `ios/` и `android/` не было: Expo генерирует их из конфигурации при prebuild или первом нативном запуске. Чтобы получить оба проекта отдельно от сборки, выполнить из корня:

```sh
npm run prebuild -- --no-install
```

Оба проекта уже сгенерированы локально: `mobile/ios/` содержит проект Xcode, `mobile/android/` — проект Gradle. Флаг `--no-install` пропускает установку зависимостей; генерация сама по себе не собирает и не запускает приложение. На чистой машине для iOS потребуется установка Pods при нативной сборке.

Эти папки игнорируются Git и воспроизводятся из `mobile/app.json`, зависимостей и config plugins. Постоянные нативные настройки вносим туда: чистый prebuild пересоздаёт нативные проекты и удаляет ручные правки в них. Подробнее: [Expo Continuous Native Generation](https://docs.expo.dev/workflow/continuous-native-generation/).

## Запуск

Первый терминал — mock для обработки импорта:

```sh
npm run mock
```

Второй терминал — собрать и запустить выбранную платформу:

```sh
npm run ios
# Или:
npm run android
```

Команды вызывают `expo run:ios` / `expo run:android`: создают нативный проект при необходимости, собирают development build и запускают Metro. Аккаунт Expo, EAS и доступ в сторы для этих локальных сборок не нужны.

После установки новых нативных зависимостей picker нужен новый development build на каждой платформе. Одного перезапуска Metro или обновления JavaScript в старой сборке недостаточно. Подробности — в [инструкции выбора файлов](docs/file-selection.md).

Для открытия Android-проекта в Android Studio из корня:

```sh
npm run android:studio
```

Подготовка среды и диагностика описаны в [инструкции Android](docs/android-troubleshooting.md).

1 ноября Android debug APK успешно собран через Gradle с JBR 21, установлен и запущен на Pixel 7 Pro Emulator / Android 17 (API 37, arm64). Android Studio Rabbit 2 | 2026.2.2 установлена в `/Applications` и открыта через `npm run android:studio` с доступным Node.js. Синхронизация проекта прошла успешно; появилась конфигурация `app`, доступна команда Run `app`, выбран Pixel 7 Pro.

Для следующих запусков уже установленной development build:

```sh
npm start
```

При проверке iOS 1 ноября Metro запускали из `mobile/` командой `npm run start -- --localhost --port 8081`, затем подключали установленный dev client. Отобразился экран «Импорт выписки»; Metro собрал 725 модулей. Подробности — в [инструкции iOS](docs/ios-troubleshooting.md).

Mock доступен на `http://127.0.0.1:8787`. Для Android-эмулятора после его запуска выполнить:

```sh
adb reverse tcp:8787 tcp:8787
```

Выбор и локальная проверка файла не обращаются к API; для них запуск mock не нужен. После нажатия «Подтвердить и отправить» клиент обращается к `http://127.0.0.1:8787`. Адрес можно изменить переменной `EXPO_PUBLIC_IMPORT_API_URL` при запуске Metro; для физического устройства нужен явно выбранный LAN-хост согласно README комплекта. Пример и поведение при сбоях — в [документации импорта](docs/import-operation.md). Нативная проверка полного сценария на обеих ОС фиксируется отдельно.

## Проверки

```sh
npm run typecheck
npm run test:mobile
npm run test:mock
```

Проверка сборки JavaScript для обеих платформ без нативного запуска:

```sh
(cd mobile && npx expo export --platform all --output-dir dist)
```

Дополнительная диагностика Expo:

```sh
npm --prefix mobile run doctor
```

`test:mobile` запускает тесты рядом с кодом фичи: валидатор и выбор файла, журнал сохранённой операции, переходы импорта и API. HTTP-тесты используют неизменённый mock с отдельным временным состоянием; проверяют реальные байты и восстановление после потерянного ответа. Точные результаты текущего прогона фиксируются в матрице приёмки. `test:mock` проверяет только выданный сервер. Эти тесты, проверка TypeScript и создание JS-бандла не заменяют системный picker и полный нативный сценарий.
