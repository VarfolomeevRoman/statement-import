## Ошибка кодировки при установке Hermes

При `pod install` или `npm run ios` установка может завершиться сообщением:

```text
Invalid `hermes-engine.podspec` file:
incompatible character encodings: BINARY (ASCII-8BIT) and UTF-8
```

Для React Native 0.88.1 и CocoaPods 1.16.2 ошибка воспроизведена в каталоге с кириллицей (`тестовые`). CocoaPods получает путь React Native из stdout Node как строку `ASCII-8BIT`. Затем Hermes объединяет её с путём `__dir__`, имеющим кодировку UTF-8. Объединение аргументов в CocoaPods завершается ошибкой ещё до запуска следующей команды Node.

Пакет `hermes-compiler` при этом установлен и разрешается обычной командой Node. Повторный запуск с `LANG=en_US.UTF-8` и `LC_ALL=en_US.UTF-8` ошибку не устранил.

В проекте хранится точечный патч `mobile/patches/react-native+0.88.1.patch`. Он помечает оба полученных из Node пути в `hermes-engine.podspec` как UTF-8: путь React Native и путь компилятора Hermes. Второй путь тоже необходимо исправлять, иначе расчёт относительного `HERMES_CLI_PATH` может оказаться неверным.

Патч применяется автоматически через `patch-package` в `postinstall` мобильного приложения:

```bash
npm --prefix mobile ci
npm run ios
```

Не используйте `--ignore-scripts` при установке: он пропустит применение патча. Не нужно вручную менять сгенерированный Podfile, переносить проект или редактировать глобальную установку CocoaPods. Патч включён в исходники проекта и повторно применяется после переустановки npm-зависимостей.

При обновлении React Native пересмотрите патч: проверьте, исправлена ли причина в новой версии, и удалите патч либо адаптируйте его. Не переносите изменение на новую версию автоматически без проверки.

30 октября 2026 года проверены чистый `npm ci` с автоматическим применением патча и успешный `pod install` (107 Pods). В debug и release xcconfig путь `HERMES_CLI_PATH` указывает на `$(PODS_ROOT)/../../node_modules/hermes-compiler/hermesc/osx-bin/hermesc`.

Установка Pods сама по себе не подтверждает успешную нативную сборку. Сборку и запуск проверяют отдельно; фактические результаты фиксируются в README и матрице приёмки.

## Прежняя несовместимость Xcode — устранена обновлением

После устранения ошибки Hermes нативная сборка 30 октября 2026 года дошла до ExpoModulesJSI и остановилась с сообщением:

```text
package 'apple' is using Swift tools version 6.2.0
but the installed version is 6.0.0
```

Окружение на момент ошибки: macOS 15.7.4, Xcode 16.2, Swift 6.0.3. Цель той проверки — iPhone 16 Pro / iOS 18.2 Simulator. Установленный `expo-modules-jsi/apple/Package.swift` требует `swift-tools-version: 6.2`; запуск приложения тогда не состоялся.

Для Expo SDK 58 официально требуется **Xcode 26.4+** ([таблица Expo](https://docs.expo.dev/versions/v58.0.0/)). По [таблице Apple](https://developer.apple.com/xcode/system-requirements), Xcode 26.4.1 требует macOS Tahoe 26.2 или новее в ветке 26.x.

Expo SDK 58 и архитектура по фичам сохранены. Пользователь обновил macOS и Xcode до 27.2 и собрал development build. Прежний блокер устранён; запуск установленного клиента подтверждён 1 ноября, как описано выше. Команда новой нативной сборки в этой проверке не выполнялась и не заявляется как проверенная.

Не исправляйте это снижением `swift-tools-version` в зависимостях: такое изменение не добавляет компилятору необходимые возможности. Повторный `pod install` не устраняет несовместимость Xcode.

## Какой файл открывать в Xcode

После успешной установки Pods открывайте рабочее пространство, включающее приложение и зависимости CocoaPods:

```bash
open mobile/ios/StatementImport.xcworkspace
```

Файл `StatementImport.xcodeproj` содержит только проект приложения. Для сборки с Pods нужен `.xcworkspace`. Если workspace ещё не появился, сначала завершите установку через `npm run ios` и устраните ошибки её вывода.

Папки `mobile/ios` и `mobile/android` генерирует Expo Prebuild. Они игнорируются Git; постоянные настройки должны воспроизводиться из конфигурации Expo, config plugins и зафиксированных зависимостей проекта.

## Симулятор и физический iPhone

Для запуска в симуляторе выберите установленный iPhone Simulator в списке устройств Xcode. Подпись для физического устройства и Development Team для такого запуска не требуются.

Если выбран подключённый iPhone, сообщение `Signing for "StatementImport" requires a development team` относится к подписи приложения, а не к Hermes. В Xcode откройте target `StatementImport` → **Signing & Capabilities**, включите **Automatically manage signing** и выберите свою **Team**. Если команды нет в списке, добавьте Apple Account в настройках Xcode.

Для диагностики окружения используйте:

```bash
xcodebuild -version
pod --version
node --version
```

При новой ошибке сохраняйте первое сообщение о причине и окружающий вывод. Последняя строка `pod install exited with non-zero code` сообщает лишь о завершении с ошибкой.
