# Выбор PDF и CSV

Внутри фичи `statement-import` реализован локальный этап: системный диалог выбора одного файла, проверка размера и содержимого, показ имени, размера и определённого формата, замена и отмена выбора. До подтверждения на экране явно написано «Файл ещё не отправлен». Действие «Подтвердить и отправить» передаёт проверенный файл модели [операции импорта](import-operation.md); сам выбор не вызывает HTTP-запрос.

## Нативные зависимости

Используются совместимые с Expo SDK 58 пакеты, зафиксированные в `mobile/package-lock.json`:

- `expo-document-picker ~58.0.4` — `getDocumentAsync`, один файл, системный Files/Documents UI, `copyToCacheDirectory: true`.
- `expo-file-system ~58.0.13` — `File`, `Directory`, `Paths.cache`, получение размера, ограниченное чтение через `FileMode.ReadOnly`, перемещение и удаление собственных копий.

Фильтр диалога включает PDF и несколько обозначений CSV, в том числе `text/plain` и `application/vnd.ms-excel`: провайдеры документов могут по-разному описывать CSV. Фильтр не является проверкой содержимого; выбранный TXT или иной файл всё равно проходит локальный валидатор. Новых запросов широкого доступа к файловому хранилищу в коде фичи нет: пользователь выдаёт доступ к выбранному документу через системный picker.

После установки зависимостей нужен новый нативный development build. Если бинарник собран до добавления picker, обновления JavaScript недостаточно. Из корня проекта:

```sh
npm --prefix mobile ci
npm run ios
# Для второй платформы:
npm run android
```

Команды выполняют локальную сборку с автолинковкой нативных модулей; для iOS устанавливаются Pods. Дальнейшие изменения только TypeScript можно проверять с уже установленным клиентом и Metro. Mock для выбора файла не нужен.

## Разделение внутри фичи

| Файл | Ответственность |
| --- | --- |
| `lib/statementFileGateway.ts` | Системный picker, приватная копия, файловые операции, безопасные сообщения об ошибках |
| `lib/validateStatementFile.ts` | Чистая проверка размера и признаков формата без Expo/React Native |
| `model/statementFileSelection.ts` | Состояние `idle/picking/validating/clearing`, один активный запрос, отмена, замена и поздние результаты |
| `model/useStatementFile.ts` | Соединение модели и gateway с React, активация и освобождение при unmount |
| `ui/StatementImportScreen.tsx` | Сведения о файле, ошибки, индикаторы, действия выбора/очистки и явное подтверждение отправки |

Контракт gateway определяется моделью и внедряется в неё. Поэтому переходы проверяются без устройства и системного диалога. `src/app` использует фичу только через её `index.ts`; `shared` и глобальных технических слоёв для этого этапа нет.

## Размер и формат

Native picker сначала делает дисковую копию выбранного документа в cache приложения. Благодаря этому JS не зависит от срока временного доступа к исходному iOS Files URL или Android `content://`. Только после завершения копирования адаптер получает фактический размер этой копии. Это не предварительное ограничение native-копирования: слишком большой документ может успеть занять место на диске до отклонения.

Размер должен быть целым положительным числом и не превышать **10 485 760 байт (10 МиБ включительно)**. При неизвестном или некорректном размере файл отклоняется. До проверки размера содержимое не загружается в JS. Затем `readBytes` читает не более **8192 байт**, а handle закрывается в `finally`; вызовы полного чтения `bytes()`, `text()` и Base64 здесь не используются.

Формат определяется по этому префиксу:

- PDF требует `%PDF-` в самом начале. Если имя заканчивается на `.pdf` или MIME заявляет `application/pdf`, но сигнатуры нет, файл отклоняется как ложный PDF. Если сигнатура присутствует, отображается PDF даже при ошибочном CSV-имени/MIME.
- CSV должен быть похож на текстовую таблицу с одинаковым числом колонок в полных строках образца и минимум двумя колонками. Поддерживаются запятая, точка с запятой и табуляция, UTF-8 BOM, LF/CRLF, кавычки, удвоенные кавычки и переносы внутри кавычек. Банковская схема и названия колонок не навязываются.
- NUL и бинарные управляющие символы в CSV-префиксе отклоняются. Не-ASCII байты остаются непрозрачными для проверки пунктуации; полноценной проверки кодировки нет. UTF-16 с NUL не поддерживается. Одноколоночный текст или первая незавершённая запись длиннее образца может быть отклонена.
- Незавершённая последняя запись обрезанного CSV-префикса не участвует в сравнении колонок. Если прочитан весь короткий файл, незакрытые кавычки считаются ошибкой.

Это ограниченная проверка признаков формата, **не полный PDF/CSV-парсер**, не проверка всех строк и не проверка безопасности документа. PDF с подходящей сигнатурой или CSV с подходящим началом может оказаться повреждённым дальше. Ошибки после первых 8 КиБ здесь не выявляются. Mock дополнительно проверяет свой контракт; для будущей приёмки используются исходные fixtures комплекта.

## Копии, отмена и ошибки

Допустимая копия перемещается из `Paths.cache/DocumentPicker` в `Paths.cache/statement-import-selections`; имя и URI исходного документа не используются как путь назначения. Эти папки сейчас принадлежат только данной фиче. Оригинальный документ и provider URI никогда не удаляются.

| Событие | Поведение |
| --- | --- |
| Отмена системного диалога | Существующий выбор и его копия сохраняются; при первом выборе экран остаётся пустым |
| Неверный или непрочитанный новый файл | Новая собственная копия удаляется, предыдущий выбор сохраняется, показывается безопасная ошибка |
| Успешная замена | Прежняя копия удаляется до переключения на новую |
| Ошибка удаления при замене | Прежний выбор сохраняется; новая копия освобождается, действие можно повторить |
| «Убрать файл» | Копия удаляется, затем выбор сбрасывается; при ошибке UI не утверждает завершённую очистку |
| Уход с экрана | Текущая копия удаляется с обработкой сбоя; поздний результат picker очищается и не возвращается в состояние |
| Подтверждение отправки | Модель импорта создаёт отдельную постоянную копию и сохраняет операцию, после чего выбор освобождает cache-копию |
| Подтверждённое сервером удаление | Очищаются обе собственные cache-папки picker. Журнал сохраняет маркер очистки, затем удаляет старые снимки и оставшиеся payload; исходный документ не затрагивается |
| «Выбрать новую выписку» | После завершённого удаления и локальной очистки экран возвращается к выбору; следующий импорт получает новый ключ |
| Новый запуск процесса | Остатки двух собственных cache-папок очищаются; неподтверждённый выбор не восстанавливается. Подтверждённая операция восстанавливается отдельно из Documents |

При неудачной фоновой очистке адаптер сохраняет URI для повторной попытки при следующем действии; новый процесс повторяет очистку собственных папок. Поэтому немедленное удаление после сбоя диска или аварийного завершения не обещается. Cache также может быть удалён операционной системой. Поэтому восстановление upload использует отдельную копию в `Paths.document/statement-import-operation` и журнал, сохранённый до первого POST. После появления сохранённого job собственная постоянная копия больше не нужна и удаляется. Подробности и ограничения — в [операции импорта](import-operation.md).

Серверное удаление отдельно подтверждается пользователем и завершается по GET со статусом `deleted`. Ошибка DELETE не очищает сведения для повтора. Если сервер уже подтвердил удаление, а локальная очистка не удалась, UI предлагает «Повторить очистку» и не разрешает новый импорт до её завершения. Оставшийся маркер `{version: 1, cleared: true}` не содержит имени, ключей или результата прежней операции.

Исключения native API могут содержать имя или URI документа. Они не логируются и не выводятся пользователю: UI получает только заранее заданные безопасные сообщения. Имя отображается локально в карточке выбранного файла. После явного подтверждения оно передаётся mock в обязательном заголовке `X-File-Name`; bytes отправляются телом запроса. Код фичи не пишет имя, URI, bytes или позиции результата в логи и аналитику.

## Проверки

Из корня:

```sh
npm run typecheck
npm run test:mobile
```

На завершении этапа выбора файла 1 ноября 2026 года TypeScript проходил, **18/18 Node-тестов** валидатора и модели прошли. После добавления импорта набор расширен; текущий результат фиксируется в [матрице приёмки](acceptance.md). Тесты выбора проверяют границу 10 МиБ, реальные bytes fixtures, ложный PDF, варианты CSV, ограниченный префикс, отмену, замену, блокировку повторного выбора, поздний ответ, неудачную очистку и безопасные ошибки. Отдельная регрессия проверяет, что отмена диалога после неудачного удаления сохраняет выбранный файл, а отложенная очистка применяется только к брошенным копиям. Нативные файловые операции не подменяются этим доказательством.

После добавления модулей обе новые native-сборки установлены и запущены: iOS `xcodebuild` — `BUILD SUCCEEDED`; Android Gradle — `BUILD SUCCESSFUL` за 28 с. На iPhone 16 Plus / iOS 18.2 подтверждено открытие Files. Выбор каждого fixture через настоящий picker, отмена, очистка и проверка Android UI фиксируются по факту в [матрице приёмки](acceptance.md). Открытый диалог и успешная сборка сами по себе не означают успешный выбор PDF/CSV или полный импорт.

Официальные API: [Expo DocumentPicker](https://docs.expo.dev/versions/v58.0.0/sdk/document-picker/), [Expo FileSystem](https://docs.expo.dev/versions/v58.0.0/sdk/filesystem/).
