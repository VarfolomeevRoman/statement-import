## Нативный iOS: восстановление, ревизии и удаление

iPhone 16 Plus Simulator / iOS 18.2, ранее установленный development build с текущим JS. Нативную сборку заново не выполняли. Перед подготовкой каждой операции проверялось, что хранилище очищено и содержит только маркер `{version:1,cleared:true}`. Синтетические payload и состояние `prepared` помещались в приватное хранилище; последующие действия выполнялись через UI приложения. Это проверяет отправку/восстановление подготовленной операции, но не системный выбор файла и первоначальное подтверждение.

### CSV: потерянный ответ и старый статус

1. Подготовлен `statement.csv`, 112 байт, без job/checkpoint. В режиме `lost_ack` нажато «Повторить» через UI. `createRequests` вырос с 4 до 5, `newJobs` — с 3 до 4, `acceptedBytes` — с 34106 до 34218: появилась ровно одна новая операция `job-demo-004`.
2. Клиент восстановил результат: 151,99 AUD и обе позиции. Payload удалён; остался ready-checkpoint с `revision=3`, без имени файла.
3. На готовом импорте включён `stale_status`, дважды нажато «Обновить статус». Серверный `getCounts` для job стал равен 2, то есть второй устаревший ответ был доставлен. UI и сохранённый checkpoint остались `ready/revision=3`.

### Ошибка удаления и полный перезапуск приложения

1. Включён `delete_failure`, удаление подтверждено через UI. Получен 503, интерфейс не утверждал завершённое удаление; `deleteRequests` вырос с 4 до 5. Ключ удаления сохранён.
2. Приложение полностью завершено через `simctl terminate`, затем открыто через `simctl openurl`. Намерение удаления сохранилось, автоматического DELETE не было: счётчик остался равен 5.
3. Mock переключён в `happy` без reset. Явный повтор через UI использовал прежний ключ для `job-demo-004`; `deleteRequests` стал равен 6. GET подтвердил `deleted`, интерфейс показал завершённое удаление. В хранилище остался только маркер очистки, собственный cache очищен.

### PDF: перезапуск до выяснения исхода отправки

Для проверки короткого окна неопределённости использован управляемый прогон без изменения исходников mock или приложения:

1. В очищенное хранилище помещена подготовленная операция с синтетическим `statement.pdf`, 33882 байта. В режиме `lost_ack` отправка запущена через UI.
2. Наблюдатель зафиксировал создание `job-demo-005`, приостановил процесс mock через `SIGSTOP` и полностью завершил приложение через `simctl terminate`. После фиксации состояния mock возобновлён через `SIGCONT`.
3. После завершения приложения на диске оставались `submission=pending`, `checkpoint=null` и payload. Это подтверждает, что клиент ещё не восстановил job до остановки. Локальное доказательство: `/tmp/statement-native-qa-cold-evidence.json`.
4. При повторном запуске приложение нашло тот же `job-demo-005` и показало 151,99 AUD. Дополнительного POST/job не возникло: `createRequests=6`, `newJobs=5` остались неизменными. Payload и имя файла удалены, сохранён `ready/revision=3`.

На готовом результате открыты подробности обеих позиций: StreamBeam — ежемесячно, 01.10.2026; BrightGrid — ежемесячно, 03.10.2026. Этот прогон подтверждает нативное восстановление неизвестного исхода после полного завершения процесса. Подготовка операции по-прежнему не доказывает работу picker или первоначального подтверждения.

### Состояние после прогона

`job-demo-005` удалён через UI в режиме `happy`; у обеих созданных операций (`job-demo-004` и `job-demo-005`) сервер подтвердил удаление. Итоговые счётчики: `createRequests=6`, `newJobs=5`, `deleteRequests=7`, `acceptedBytes=68100`. Это накопительные значения рабочего mock, а не число операций только этого прогона.

В каталоге операции iOS остался ровно один маркер `{version:1,cleared:true}`; `DocumentPicker` и `statement-import-selections` отсутствуют или пусты. SHA-256 исходных фикстур не изменился. После экрана «Импорт удалён» нажато «Выбрать новую выписку», приложение оставлено на начальном экране. Состояние Android этим нативным прогоном не изменялось.

## Проверка исходников

В просмотренном коде не обнаружены прямые вызовы логирования содержимого файла или SDK аналитики/crash-отчётов. Проверены механизмы очистки собственных копий, прокручиваемый экран, safe area и минимальная высота кнопок 52. Это аудит кода: он не заменяет анализ фактических runtime-логов или визуальный прогон с крупным системным шрифтом и на небольшом экране.

## Ограничения управления интерфейсом

- iOS: системный Files открылся, но инструмент не смог выбрать файл координатным нажатием ни в компактном, ни в полном окне — `noWindowsAvailable`.
- Android: получение интерфейса Android Studio через инструмент управления завершалось `timeoutReached`.

Поэтому полный путь системный picker → выбор PDF/CSV → подтверждение → результат на обеих платформах не засчитан этим прогоном. Нативные сценарии `lost_ack`, `stale_status` и DELETE 503 с повтором на Android также не засчитаны. Подготовка файлов или состояния приложения через инструменты разработчика не доказывает работу picker.

Оставшиеся пункты и ранее полученные нативные доказательства находятся в [матрице приёмки](acceptance.md). Успешные автотесты не означают, что все её пустые чекбоксы закрыты.
