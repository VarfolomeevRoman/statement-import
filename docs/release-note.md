# Релизная записка — 0.1.0

Подготовлена 2026-11-02 для тестового задания. Это кандидат на сдачу в виде кода и локальных development builds; production-распространение не выполнялось. Актуальные доказательства и непроверенные сценарии — в [матрице приёмки](acceptance.md).

## Изменения

Реализованы системный выбор PDF/CSV, локальная проверка до 10 МиБ, подтверждение отправки настоящих байтов, асинхронный результат с подробностями, восстановление без дубликатов, удаление с сохранённым ключом и повтором. UI различает очередь и обработку. После однозначного отказа первого POST с 413/415 можно выбрать другой файл; неизвестный исход сохраняет ключ для восстановления.

## Разрешения и окружение

- Фича использует системный выбор одного документа, на Android — `ACTION_OPEN_DOCUMENT`; код picker не запрашивает runtime-доступ ко всему хранилищу. Доступ к исходному документу нужен для создания собственной копии.
- В текущем сгенерированном Android manifest фактически объявлены `INTERNET`, `READ_EXTERNAL_STORAGE` и `WRITE_EXTERNAL_STORAGE` с `maxSdkVersion=32` (из Expo FileSystem), а также `SYSTEM_ALERT_WINDOW` и `VIBRATE`. Отсутствие широкого runtime-запроса picker не означает отсутствие этих деклараций в сборке. Для будущего production-бинарника следует отдельно проверить итоговый merged manifest и удалить ненужные разрешения через воспроизводимую конфигурацию Expo.
- iOS development build содержит описание доступа к локальной сети для Expo Dev Launcher и разрешает локальное сетевое соединение; произвольные ATS-загрузки выключены. В app-конфигурации нет запросов камеры, микрофона, геолокации или медиатеки.
- Используются Metro и локальный HTTP mock, для Android — `adb reverse`. Тестовый API не предназначен для публичного доступа. Новых нативных зависимостей в доработке отказов и статусов не добавлено.

## Копии, срок хранения и очистка

До подтверждения собственная копия находится в cache; действие «Убрать файл», успешная замена, уход с экрана и следующий запуск очищают её. Отмена самого системного диалога сохраняет предыдущий выбор. Подтверждённая операция сохраняет payload в приватном Documents и минимальный журнал. Байты нужны до появления сохранённого job ID или разрешённой отмены окончательно отклонённого файла; после этого удаляются. При неизвестном исходе копия сохраняется для безопасного повтора. При `deleted` очищаются cache, payload и прежние снимки; остаётся только маркер `{version:1,cleared:true}` без ключей, имён и результата. Сбои очистки допускают повтор. Оригинал пользователя не удаляется.

Собственное шифрование и исключение Documents из системных backup не настроены; Android объявляет `allowBackup=true`. Sandbox не равен зашифрованному приложением хранилищу, поэтому отсутствие копий в резервных копиях не обещается. Результат хранится в памяти и после запуска запрашивается через GET. Приложение не добавляет байты, имена, URI и описания списаний в логи или аналитику. Mock хранит метаданные и SHA-256, но не байты выписки.

## Условия остановки распространения

Дубликат job после повтора, сообщение об удалении без подтверждающего GET или попадание документа/его имени в логи — причины остановить распространение и исправить дефект до продолжения. Для данного mock проверка выполняется сопоставлением UI, журнала и серверных счётчиков. Production-мониторинг не подключён; его следует строить на кодах переходов и обезличенных счётчиках, без содержимого документов.

## Граница JS/OTA и нового бинарника

Совместимые изменения UI, сообщений и JS-модели могут доставляться JS-обновлением при настроенном механизме OTA и совместимом native runtime. В проекте OTA-доставка не настроена; сейчас JS загружает Metro. Изменения нативных модулей, разрешений, native-конфигурации, Expo/RN или патча Hermes требуют prebuild и нового нативного бинарника. Изменения схемы журнала требуют совместимой миграции независимо от способа доставки: старые записи без `submission` остаются с неизвестным исходом.

## Перед сдачей

Кандидат подтвердил ручной прогон и запись видео iOS/Android 2026-11-03 и предоставляет видео отдельно. Автотесты повторно прошли: 86/86 клиента, 6/6 mock, TypeScript без ошибок. Установка зависимостей, JS export и prebuild в чистой файловой копии проверены. Маленький экран/крупный шрифт и полная нативная сборка из чистого clone остаются непроверенными; инструментальные доказательства и подтверждения кандидата разделены в [матрице](acceptance.md).
